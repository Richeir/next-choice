# 系统架构设计

本文档描述「股票分析网站」MVP0 的整体架构与前后端数据流。

## 1. 架构总览

前后端分离的单体应用（MVP0 阶段不需要微服务）：

```
┌──────────────────────────────────────────────────────────┐
│                        前端 (React)                       │
│  首页 / 股票列表 / ETF 列表 / 详情页                        │
└──────────────────────────┬───────────────────────────────┘
                           │  HTTP (REST / JSON)
┌──────────────────────────▼───────────────────────────────┐
│                        后端 (Nest.js)                     │
│  模块：证券信息 / K线 / 分析 / 统计 / 配置                  │
│  数据访问层：Repository 封装 SQLite 读写                   │
└───────────────┬──────────────────────────┬───────────────┘
                │                          │
      ┌─────────▼─────────┐       ┌────────▼─────────┐
      │  SQLite (本地)     │       │  LLM (单模型)     │
      │  11 张表           │       │  买入判断/持有天数 │
      └───────────────────┘       └──────────────────┘

外部数据源：BaoStock（Python Library，离线采集脚本写入 SQLite）
```

## 2. 组件职责

| 组件 | 职责 |
|------|------|
| **前端 (React)** | 渲染页面、展示列表/详情/统计、调用后端 REST API |
| **后端 (Nest.js)** | 提供 REST API、读写 SQLite、调用 LLM 分析、调度采集 |
| **SQLite** | 本地持久化，存储证券信息、K 线、分析结果 |
| **LLM** | 根据 K 线与信息判断是否值得买入、给出持有天数预测 |
| **BaoStock** | 外部数据源，经 Python 采集脚本拉取数据入库 |

## 3. 数据流

### 3.1 数据入库流（离线）

```
BaoStock (Python) --采集脚本--> SQLite (stock_info / etf_info / kline_*)
```

采集由独立 Python 脚本完成，写入 SQLite 后，Nest.js 只读数据库，不直接依赖 BaoStock。

### 3.2 分析流（按需/定时）

```
Nest.js 定时任务
  ├─ 从 SQLite 读取最新 K 线与证券信息
  ├─ 组装提示词（读自全局配置）
  └─ 调用 LLM  --> 输出 JSON --> 回填 stock_analysis / etf_analysis
```

MVP0 支持单只标的触发分析与批量定时分析两种方式。

### 3.3 页面数据流

```
React --GET /api/...--> Nest.js --SQL--> SQLite --> JSON --> React
```

- 首页统计：`GET /api/stats`（股票数 / ETF 数 / 已分析数 / 已分析次数）
- 列表页：`GET /api/stocks`、`GET /api/etfs`（分页 + 排序 + 过滤）
- 详情页：`GET /api/stocks/:code`、`GET /api/stocks/:code/analysis`（最新分析）

详见 [api-design.md](api-design.md)。

## 4. 关键设计决策

- **前后端分离**：React 与 Nest.js 独立部署，通过 REST JSON 通信，便于前端富交互。
- **数据源解耦**：BaoStock 只由 Python 采集脚本接触，Nest.js 不依赖 Python 运行时，降低耦合。
- **分析表按历史保存**：分析结果带 `date` 主键，保留时序，便于回看评级变化与回测。
- **LLM 配置全局化**：提示词模板存于配置（文件/DB），后续迭代可直接改模板，不改代码。见 [llm-analysis.md](llm-analysis.md)。

## 5. 错误处理与边界

- **数据缺失**：证券信息或 K 线未采集时，接口返回空列表/空详情，前端展示占位，不报错。
- **LLM 超时/失败**：分析接口对 LLM 调用设置超时与重试；失败时写入 `llm_analysis` 失败标记，前端提示"分析失败可重试"。
- **无效代码**：`GET /api/stocks/:code` 对不存在的 code 返回 404。
